Build Your Agent in Copilot Studio

Copilot Studio is the place to build agents that do more than Agent Builder agents. In Copilot Studio, you select the harness for each agent, and the harness decides what the agent can do. In this module, you learn the full anatomy of an agent. Then you compare the harnesses and build one agent on each of the two main harnesses.

9.1 Anatomy of an Agent

An LLM on its own is not an agent: it generates text and stops. What turns it into something that performs work is the harness — the runtime scaffolding around the model. The harness decides when to call the model, what to send it, how to read what comes back, and which tool to call next. It also manages conversation state and context, applies approval policies, and keeps a multi-step task moving.

Agent = LLM + Harness

Notice what that means: neither term is something you write. You select a model and you select a harness. What you author is the third thing — the design layer — and it has three components: instructions, knowledge, and tools & skills. The design layer is built around the harness, never independently of it.

Anatomy of an agent

You select the model and the harness — Copilot chat, Standard or GitHub Copilot; you author the design layer — instructions, knowledge, and tools & skills. The harness decides which of the three you can express and how richly, so choose the harness first, then design into it.

The harness you pick is inherited, not negotiated: instruction ceilings, whether tools can be orchestrated across steps, and whether knowledge is reasoned over or merely retrieved are all harness properties. Read “not a focus” as the harness won’t do it for you rather than impossible — on the standard harness, files are a wiring job you author; on the GitHub Copilot harness they are a capability you inherit.

The planning rule. Choose the least capable harness that still clears the requirement, then design instructions, knowledge and tools to fit it. Capability you don't need is cost, governance surface and latency that you do pay for.

Common mistake — blaming the model for what the harness owns. “The agent forgot what we discussed” is a state-and-context problem. “It stopped after one step” is an orchestration-loop problem. “It couldn't produce the Excel file” is a harness-capability problem. Swapping the model fixes none of these.

9.3 Build your Standard Harness Agent

Use the standard harness for rule-based agents and structured conversations. You define topics and rules. The agent follows the paths that you build.

Where is the standard harness? The Agent, Workflow and App tiles on the Copilot Studio Home page use the GitHub Copilot harness. To build on the standard harness, select Other ways to build, then use the Build with standard orchestration section.

Do these steps:

1

Go to copilotstudio.microsoft.com and sign in. On the Home page, select Other ways to build.

2

Under Build with standard orchestration, select Agent (Standard). Other path: Agents › the arrow next to New agent › Agent (Standard).

3

In Name your agent, type a name. If necessary, open Agent settings (Optional) to set the language, the solution and the schema name. Select Create.

4

On the Overview page, add a description (up to 1,024 characters) and select the model. Write the Instructions. Add Knowledge, Tools and Triggers. Use the Topics tab for fixed conversation paths. To run a fixed procedure, add an agent flow as a tool (see 10.3). Code interpreter is opt-in: your admin must enable it first.

5

Select Test to open the Test your agent pane. Ask questions and check the answers.

6

Select Publish. Then, on the Channels tab, add the Teams and Microsoft 365 channel to use the agent in Teams and Microsoft Copilot. A trial license cannot publish.

Copilot Credits and Copilot Studio capacity. Copilot Credits are the billing unit. Copilot Studio capacity is the pool of Copilot Credits that your organization buys (prepaid packs or pay-as-you-go) and assigns to environments. Agents and flows consume Copilot Credits from this capacity.

Licensing. Standard harness agents keep the existing Copilot Studio licensing model. A test in the test pane does not consume Copilot Studio capacity. A published agent consumes Copilot Credits from Copilot Studio capacity. For users with a Microsoft Copilot license, classic answers, generative answers and Microsoft Graph tenant grounding in Copilot Chat, Microsoft Teams or SharePoint do not consume Copilot Studio capacity.

9.4 Build your GHCP Harness Agent

Use the GitHub Copilot (GHCP) harness for complex, multistep business processes. The agent reasons through a goal step by step. If a tool call fails, it tries again or selects another path. It creates and edits Word, Excel, PowerPoint and PDF files natively, and it supports skills and memory.

Do these steps:

1

Go to copilotstudio.microsoft.com. On the Home page, select the Agent tile (GitHub Copilot). Other path: Agents › New agent.

2

On the Build tab, change Untitled Agent to a name. Write the Instructions: what the agent must do, what is in and out of scope, how it communicates, and when it asks for input.

3

In the right pane, set the Model (Auto by default). Add Triggers, Skills, Tools, Knowledge and Connected agents. Work IQ (in Tools) and Search all websites (in Knowledge) are added by default. Turn on Memory (preview) if the agent must keep preferences and progress across sessions.

4

To edit a file where it is stored, add the SharePoint or OneDrive for Business connector as a tool. Use Get file content to read the file and Update file to write it back. Then test the agent on the Preview and Evaluate tabs.

5

Select Review, then select Publish. Use the Monitor tab to watch the agent after you publish it.

Other path (preview): describe your process in the prompt box on the Copilot Studio Home page. Copilot Studio then makes a deterministic workflow, a conversational agent, or a combination of both.
