Build Your Own Agent — Agents, Agent Builder & Copilot Studio

When you chat with Microsoft 365 Copilot — or use one of its built-in, first-party agents — you're prompting: typing what you want, each time. An agent turns that around. Instead of prompting, you save your prompt as the agent's instructions, so it works that way every time. This module goes in three steps: what an agent actually is (and what a harness is), how to build one with no code in Agent Builder, how to package repeatable work as skills, and when to graduate to Copilot Studio.

From prompting to building

Everything so far has been you typing what you want. An agent is that prompt made permanent — written once as instructions, pointed at the right knowledge, and handed to whoever needs it.

Agents & harnesses — what you're actually choosing

An LLM on its own is not an agent: it generates text and stops. What turns it into something that performs work is the harness — the runtime scaffolding around the model. The harness decides when to call the model, what to send it, how to read what comes back, and which tool to call next. It also manages conversation state and context, applies approval policies, and keeps a multi-step task moving.

Agent = LLM + Harness

Notice what that means: neither term is something you write. You select a model and you select a harness. What you author is the third thing — the design layer — and it has exactly three components.

I

Instructions

The agent's role, scope, tone and boundaries — and how it should call resources, fill tool inputs and respond.

K

Knowledge

The grounding sources it answers from — SharePoint, files, connectors, approved websites — so answers are anchored, not invented.

T

Tools

What it can do beyond talking — connectors, APIs, MCP servers, flows, and other agents it can invoke.

The design layer is built around the harness, never independently of it. The harness decides which of the three you can express, how richly, and whether some are available at all. So: choose the harness first, then design into it.

The harness you pick is inherited, not negotiated: instruction ceilings, whether tools can be orchestrated across steps, and whether knowledge is reasoned over or merely retrieved are all harness properties. Read “not a focus” as the harness won’t do it for you rather than impossible — on the standard harness, files are a wiring job you author; on the GitHub Copilot harness they are a capability you inherit.

The planning rule. Choose the least capable harness that still clears the requirement, then design instructions, knowledge and tools to fit it. Capability you don't need is cost, governance surface and latency that you do pay for.

Common mistake — blaming the model for what the harness owns. “The agent forgot what we discussed” is a state-and-context problem. “It stopped after one step” is an orchestration-loop problem. “It couldn't produce the Excel file” is a harness-capability problem. Swapping the model fixes none of these.

Instructions, knowledge sources & sharing
Configuring your Agent in Agent Builder

On the Configure tab you shape the agent through four parts.

1

Instructions

Tell the agent how to behave — its tasks, tone, rules, steps and examples. This is where your prompt becomes the agent’s standing brief. (Up to 8,000 characters.)

2

Knowledge

Choose the sources the agent grounds its answers in. Premium can use files, emails, chats, meetings, websites and the org chart; Basic is limited to specific websites.

3

Skills & capabilities

Add Skills (preview) to specialize the agent on a task. Capabilities now arrive switched on — every new agent can write code, create Word, Excel and PowerPoint files, and generate graphics — and the controls stay available if you want to turn one off.

4

Suggested prompts

Add starter prompts (a Title and a Message) so people know how to begin with your agent.

Character limits. Name — up to 30 characters. Description — up to 1,000. Instructions — up to 8,000. Keep instructions focused; for longer or more complex logic, split it into steps or move to Copilot Studio. Learn more →

Considerations: Grounded Knowledge vs. Attached Cloud Files

When you hand Copilot documents to work from, there are two ways to do it — and they behave differently. Grounded knowledge is a knowledge source you wire into the agent at build time (for example, a SharePoint folder) — it lets Copilot find the relevant bits across many documents. Attached cloud files are files you attach to the prompt at runtime — they point Copilot straight at specific files so it reads them thoroughly. In short: grounded knowledge optimizes for relevance across a library; attached files optimize for completeness on the few you attach.

Grounded knowledge (build time) — use when…
  • You're searching a large document library
  • You're answering FAQ-style questions
  • You're discovering things — "which policy mentions X?", "what are the common themes?"
Attached cloud files (at the prompt) — use when…
  • Legal or policy review and validation
  • Exception analysis
  • "Make sure you don't miss anything" tasks on specific files

Skills — packaging work your agent repeats

Agent Builder gives your agent 8,000 characters of instructions. That is a real design budget, and it is the reason skills exist. A skill is a modular capability you add to an agent so it performs a specific task more reliably and repeatably — not more knowledge, and not another tool, but a packaged procedure with the assets and scripts that procedure needs travelling alongside it. An agent is the “who”; a skill is the “how”.

SourceCustom skills in declarative agents (preview) — Microsoft LearnModule 6 · 8 of 12
The anatomy of a skill

A skill is a file directory. Exactly one file is mandatory.

1

SKILL.md — required

YAML front matter carries the name and description — what the orchestrator reads to decide when the skill applies, so they're load-bearing, not labels. Below it, the procedure itself.

2

Resource files — optional

The assets the task needs: branded templates, KPI definitions, reference tables, schemas.

3

Scripts — optional

Code you control instead of code the model improvises — the same transformation, the same chart, every run.

A worked example from the documentation: a finance team's quarterly business review skill bundles the instructions for producing the review, scripts that transform the data and build the charts, and assets such as financial models, KPI definitions and branded slide templates.

SourceCustom skills in declarative agents (preview) — Microsoft LearnModule 6 · 9 of 12
Why a skill instead of longer instructions
Optimized context

Progressive disclosure — the model loads a skill's instructions and contents only when the task needs them, so context stays focused as your skill library grows.

Scale without quality loss

Decompose complex guidance into modules: longer, more specific direction without degrading instruction-following or hitting the 8,000-character ceiling.

Reusable assets

Instructions, resources and scripts ship together as one integrable capability.

Enterprise-ready

Scripts run in a secure sandbox, sensitivity labels on skill files are retained and honored, and files are stored in tenant-scoped SharePoint Embedded containers.

Does this change the harness? No. Agent Builder still produces declarative agents on the Copilot chat harness — custom skills are a new component inside the agent, not a migration to a different runtime. Skill scripts run in a sandbox with no network access, no package installation and no authenticated network calls; connectors, API plugins and MCP servers stay available to the agent through the orchestrator, but scripts can't reach them. Skills raise the ceiling of this harness — longer, more repeatable instruction sets — without moving the walls. If your requirement fails on memory, reasoning loops, transactions, file editing or external publishing, skills won't rescue it; a harness change will.

Copilot Studio — the maker harness, and when to graduate

Copilot Studio is where the other two harnesses live. The standard harness is the classic Copilot Studio most makers know: you author topics, prompts and paths, and the agent responds consistently to well-understood requests — an internal help desk that answers common questions and routes simple ones through a flow. The GitHub Copilot harness is the most capable option: it takes a goal, breaks it into steps, calls tools across connectors, knowledge, MCP and connected agents, adjusts when a step fails, natively creates and edits Word, Excel, PowerPoint and PDF, and supports skills and memory. It is generally available in Copilot Studio — you choose the harness when you create an agent — and usage is billed in Copilot Credits, including build and test.

Stay in Agent Builder when…

One person's job, answered from knowledge you can attach or reach through Work IQ; one grounding pass plus one tool call produces a complete answer; the deliverable is a generated file; publishing is to your team.

Graduate to Copilot Studio when…

You hit the walls: memory across a task, reasoning loops, transactions against a line-of-business system, editing an existing document in place, autonomous or event-triggered runs, multi-user orchestration, or reach outside the tenant.

Reach for the lightest tool that does the job. The same three tiers that power Copilot also decide where you build an agent and what the agent you build can do — you only graduate to Copilot Studio when an agent needs Tier-3 reach.

Always check these capabilities and boundaries against the latest Microsoft Learn release every time you do solutioning.

Tier 1

Microsoft 365 Copilot Chat (Basic)

Build with: Agent Builder (Basic)

Create simple agents from instructions and the knowledge you attach. No Work IQ — the agent can't reach your wider M365 data on its own.

  • Answers from instructions + the web
  • Grounds on files you attach or upload
  • One user, person-in-the-loop
Tier 2

Microsoft 365 Copilot (Premium)

Build with: Agent Builder

Create no-code agents grounded on Work IQ — your files, emails, chats & SharePoint — on GPT models.

  • Reads & acts over your own M365 data
  • Multi-step work within one identity
  • Generates documents, decks & Excel; scheduled digests
  • Person-reviewed output
Tier 3

Copilot Studio (extensibility)

Build with: Copilot Studio (low-code, IT-governed)

Build custom, centrally governed agents wired into line-of-business systems via connectors and Power Automate.

  • Line-of-business system integration
  • Autonomous event-/schedule-triggered runs
  • Cross-entity / multi-user orchestration
  • External / non-tenant access (no Entra ID)
  • Choose GPT or Anthropic models in the agent's configuration

The usual path — prototype, then harden. Prove the idea fast in Agent Builder (Tier 1–2), then rebuild it in Copilot Studio (Tier 3) when it needs system connectors, autonomous triggers, multi-user orchestration or external reach. If a task stays within one person's identity and a human reviews the output, you usually don't need Copilot Studio at all.
