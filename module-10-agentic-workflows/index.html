Module 10

Build your Agentic Workflow in Copilot Studio

An agent decides its next step itself. Sometimes you must have the same steps each time. For this work, Copilot Studio has flows. In this module, you learn what an agentic workflow is. Then you compare the two types of flow and build one of each.

10.1 Anatomy of an Agentic Workflow

An agentic workflow is an automation that has a fixed path with AI steps on it. The maker designs the path before it runs. AI actions and agents do some of the steps. Microsoft describes workflows as automations that “combine deterministic automation with AI-driven actions, such as agent handoffs and native AI nodes.”

Agent = LLM + Harness

The model plans the steps, selects tools and decides when the work is done. The harness is “the operating layer between the model and the agent’s configuration”. Your instructions, tools and knowledge go through it.

Flow = Trigger + Actions

The maker designs the path before it runs. The path has rule-based branches. The harness under the flow decides the designer, the AI steps and the billing.

Trigger

On demand, on a schedule, on an event, or when an agent calls it

→

Connector

Microsoft 365, third-party or custom

→

AI capability

Generate text, process documents, run a prompt, call an agent

→

Human in the loop

Request information or approval

→

Built-in tools

Branches, loops, data operations, child flows

Same anatomy, two harnesses. An agent flow is Trigger + Actions on the standard harness. A workflow is Trigger + Actions on the GitHub Copilot harness, with native Agent, Copilot and Classify nodes.

AspectAgent = LLM + HarnessFlow = Trigger + Actions
Who decides the pathMostly the model, when it runs.The maker, when the maker designs it.
Where the LLM isAt the center. It reasons over each turn and selects tools.Only in the AI actions or nodes that you add.
OutputChanges for each request.The same path each time.
How they work togetherAn agent can call a flow as a tool.A flow can call an agent with an AI action or an Agent node.

10.2 Comparison Table: Agent Flows vs Workflows

Copilot Studio has two types of flow. They have the same anatomy (Trigger + Actions) on a different harness.

AspectAgent Flows (Standard Harness)Workflow (GHCP Harness)
What it isAn automation on the standard harness, managed with classic agents.An automation on the GitHub Copilot harness.
Where you buildHome › Other ways to build › Agent flows (Standard).
Or Workflows › More create options (next to New workflow) › Agent flows.		Home › the Workflow tile (GitHub Copilot).
Or Workflows › New workflow.
How you buildDescribe it in natural language, or drag and drop in the designer.Add a trigger and actions on a redesigned visual canvas.
AI actions — key differenceGenerate text, process documents, run a prompt, call an agent, reply to a calling agent.The same AI actions, plus native nodes: Agent, Copilot (runs Copilot Chat or a Cowork task, or calls agents like Researcher and Analyst), Classify and Extract.
Human in the loopRequest approval or information.Request information. For an approval, add a Yes/No input. There is no separate approval action.
TestingTest in the designer or from the agent’s test chat.Node-level testing: test one node, or the full workflow.
Path — key differenceDeterministic: the same input always gives the same output.Predictable, but results can change when actions use AI or changing data.
Copilot Credits consumptionEach action that runs consumes Copilot Credits.Each action that runs consumes Copilot Credits.
Build and test billing — key differenceTest runs do not consume Copilot Credits.Building and testing can consume Copilot Credits.

How to select. Use an agent flow when every step is fixed and the same input must give the same output. Use a workflow when the path is fixed but some steps need AI judgment, for example to classify an item or to call Copilot or an agent. You cannot convert an agent flow into a workflow.

10.3 Build your Agent Flow (Standard Harness)

An agent flow gives the same output for the same input. Use it for fixed, repeated procedures. Agent flows are on the standard harness, so you start from Other ways to build.

Do these steps:

1

Go to copilotstudio.microsoft.com. On the Home page, select Other ways to build.

2

Under Build with standard orchestration, select Agent flows (Standard). Other path: Workflows › the arrow next to New workflow › Agent flows.

3

To describe the flow in natural language, select Copilot in the designer toolbar. Review the plan, refine it and confirm it.

4

Or build the flow yourself in the Create workflow pane. Search for an action or connector, or start with a trigger from Built-in tools or By connector. To let an agent call the flow, use the When an agent calls the flow trigger.

5

Select Flow checker, then Test. A test does not consume Copilot Studio capacity. Select Save draft, then Publish. Add the agent flow as a tool to your standard harness agent (see 9.3).

When a new request arrives in the Purchase Requests list, check the amount. If it is more than 5,000, send it to the finance manager for approval. Then update the status and email the requester.

Billing. Each action consumes Copilot Credits from Copilot Studio capacity. When an agent calls the flow for a signed-in user with a Microsoft Copilot license, the flow run does not consume Copilot Studio capacity. This does not apply to autonomous runs.

10.4 Build your Workflow (GHCP Harness)

A workflow mixes fixed steps with native AI nodes. Use it when the path is fixed but some steps need judgment. Workflows are on the GitHub Copilot harness, so you start from the Workflow tile on the Home page.

Do these steps:

1

Go to copilotstudio.microsoft.com. On the Home page, select the Workflow tile (GitHub Copilot). Other path: Workflows › New workflow.

2

Change Untitled workflow to a name.

3

Select the Start node to set the trigger: on demand, on a schedule or on an event. To let an agent call the workflow, use the When an agent calls the flow trigger and a Respond to the agent action.

4

Add steps from the Add pane, or select + next to a node: Agent, Classify, Extract, Copilot, Human review, Connector, Function, Variable, If/Else, Loop and Note.

5

Test one node with Test this node, or select Test (▷) to run the full workflow. Correct all errors. Select Review, then Publish. You cannot publish a workflow that has errors.

Every Monday at 8 AM, read the new support tickets. Classify each ticket as billing, technical or account. Send technical tickets to the support agent. Ask Copilot to write a weekly summary and post it in the team channel.

Billing. Workflows consume Copilot Credits from Copilot Studio capacity, from the first build step, including preview and testing. They do not need a separate Power Automate license.
